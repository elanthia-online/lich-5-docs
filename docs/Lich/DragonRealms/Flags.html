Overview

Manages named event flags and matchers for game line pattern matching.

The Flags class provides thread-safe storage for event flags that track whether game output has matched regex patterns added by scripts. Matchers are stored in a frozen hash that is atomically swapped during add/delete operations, allowing the game thread to safely iterate over patterns while scripts modify the set.

Examples:

Add a flag matching damage lines

Lich::DragonRealms::Flags.add("hit", "You strike the", /deals? \d+ damage/)
# ...
if Lich::DragonRealms::Flags["hit"]
  respond("Damage matched!")
end

DRParser.check_events iterates @@matchers on the game thread while scripts add and delete flags from their own threads. Inserting a key into a hash another thread is iterating raises "can't add a new key into hash during iteration", so writers never mutate @@matchers in place: they build a new hash and swap the reference, and an iteration in progress keeps walking the hash it started with. The mutex stops two writers from both copying the same hash and losing an update, and makes record_match's check-and-write atomic against add and delete.

.add(key, *matchers) ⇒ Array<Regexp>

Registers a new flag with regex matchers for game output.

Patterns can be Regexp objects or strings; strings are converted to case-insensitive regexes. The flag is initialized to false and will be set to the MatchData of the first matching pattern when the game outputs a matching line.

def self.add(key, *matchers)
  regexes = matchers.map { |item| item.is_a?(Regexp) ? item : /#{item}/i }.freeze
  @@matchers_lock.synchronize do
    @@flags[key] = false
    @@matchers = @@matchers.merge(key => regexes).freeze
  end
  regexes
end

def self.delete(key)
  @@matchers_lock.synchronize do
    @@matchers = @@matchers.reject { |k, _| k == key }.freeze
    @@flags.delete key
  end
end

def self.record_match(key, regexes, matches)
  @@matchers_lock.synchronize do
    @@flags[key] = matches if @@matchers[key].equal?(regexes)
  end
end
