Overview

Module for common moonmage script utilities in DragonRealms. Provides methods for celestial observations, divination tools, moon weapon handling, and moonwatch data management.

def await_moonwatch_data(seen_running, timeout)
  deadline = Process.clock_gettime(Process::CLOCK_MONOTONIC) + timeout
  loop do
    running = Script.running?('moonwatch')
    return true if running && moon_data_ready?

    if running
      seen_running = true
    elsif seen_running
      Lich::Messaging.msg("bold", "DRCMM: moonwatch stopped before its moon data was ready. Moon data is unavailable.")
      return false
    end

    if Process.clock_gettime(Process::CLOCK_MONOTONIC) >= deadline
      if seen_running
        Lich::Messaging.msg("bold", "DRCMM: moonwatch did not publish moon data within #{timeout} seconds. Moon data is unavailable.")
      else
        Lich::Messaging.msg("bold", "DRCMM: moonwatch did not start within #{timeout} seconds. Moon data is unavailable.")
      end
      return false
    end

    pause MOONWATCH_POLL_INTERVAL
  end
end

.check_moonwatch(timeout: MOONWATCH_READY_TIMEOUT) ⇒ Boolean

Makes sure moonwatch is running, starting it if needed, and waits a bounded time for it to publish real moon data (see moon_data_ready?).

When moonwatch is running and the data is ready, this returns at once. When moonwatch is running but the data is not ready yet (it was started elsewhere, for example by autostart, and is still starting up), this waits for the data. If any wait for the data (this one or the one after starting moonwatch) times out while moonwatch keeps running, later calls return false at once instead of waiting again, until the data becomes ready or moonwatch is seen stopped. That includes calls already queued behind another caller's start or wait. When another caller's start is in progress, it waits for that start to finish (returning as soon as the data is ready), allowing MOONWATCH_LOCK_WAIT_MARGIN beyond the timeout. If that wait times out (the other caller's script is paused, or its start is stuck), later calls do not wait on that start again until it finishes: they return false at once while moonwatch is not running, and wait only for the data of a running moonwatch. Otherwise it clears the saved UserVars.moons and UserVars.sun (they may be stale), starts moonwatch and waits until moon_data_ready? is true. The wait ends early, with a message, when moonwatch cannot be found or stops before publishing, and ends at the deadline when it never starts or never publishes. The saved data is never restored on failure, so moon and sun checks see nothing up rather than stale timers. After such a failure, while moonwatch is not running, calls return false without starting it again until MOONWATCH_RESTART_COOLDOWN seconds have passed; a moonwatch started some other way in the meantime is still used.

A nil from start_script is not treated as a failure unless moonwatch cannot be found (see moonwatch_findable?): Lich also returns nil while another start of moonwatch is still in progress, so in that case this waits (up to the deadline) for that start to finish.

The timeout bounds each wait separately. A caller queued behind another caller's start waits up to timeout + MOONWATCH_LOCK_WAIT_MARGIN for the lock. If, once it has the lock, it finds a moonwatch that was started elsewhere in the meantime and has not published yet, it then waits up to timeout for that data too. So one call can take up to 2 * timeout + MOONWATCH_LOCK_WAIT_MARGIN (21 s by default) in that sequence; every other call takes at most timeout + the margin.

Only waits of at least MOONWATCH_READY_TIMEOUT set the stall latch or the stuck-start latch. A caller passing a shorter timeout gets false when its own wait runs out, but does not make other callers skip theirs.

Parameters:

  • timeout (Numeric) (defaults to: MOONWATCH_READY_TIMEOUT) —

    seconds to wait for another caller's start to finish (plus MOONWATCH_LOCK_WAIT_MARGIN), and again for moonwatch to publish (after starting it, or when it is already running). Must be a positive, finite number.

Returns:

  • (Boolean) —

    true when moonwatch is running and has published real moon data; false when moon data is unavailable

Raises:

  • (ArgumentError) —

    when timeout is not a positive, finite number

def check_moonwatch(timeout: MOONWATCH_READY_TIMEOUT)
  validate_moonwatch_timeout!(timeout)

  if Script.running?('moonwatch')
    return moonwatch_data_ready! if moon_data_ready?
    return await_running_moonwatch(timeout) unless MOONWATCH_START_LOCK.locked?
  else
    @moonwatch_data_stalled = false
  end

  lock_deadline = Process.clock_gettime(Process::CLOCK_MONOTONIC) + timeout + MOONWATCH_LOCK_WAIT_MARGIN
  start_generation = @moonwatch_start_generation
  until MOONWATCH_START_LOCK.try_lock
    # The other start may publish while the lock is still held (its
    # holder can be paused or slow to return), so keep checking. When
    # the holder's wait has just timed out on a running moonwatch (the
    # stall latch is set), stop waiting too. When an earlier wait on
    # this start timed out (the holder is stuck), wait only on a running
    # moonwatch itself, not on the holder.
    if Script.running?('moonwatch')
      return true if moon_data_ready?
      return false if @moonwatch_data_stalled
      return await_running_moonwatch(timeout) if @moonwatch_start_stuck
    elsif @moonwatch_start_stuck
      return false
    end
    if Process.clock_gettime(Process::CLOCK_MONOTONIC) >= lock_deadline
      Lich::Messaging.msg("bold", "DRCMM: Timed out waiting for another start of moonwatch to finish. Moon data is unavailable.")
      note_moonwatch_start_stuck(start_generation) if full_moonwatch_wait?(timeout)
      return false
    end
    pause MOONWATCH_POLL_INTERVAL
  end

  begin
    # A stuck start, if any, has released the lock.
    moonwatch_start_lock_taken
    # Another caller started moonwatch (or another wait on it ran) while
    # this one waited for the lock: wait for its data, honouring the latch.
    return await_running_moonwatch(timeout) if Script.running?('moonwatch')
    if moonwatch_restart_blocked?
      # A start failed moments ago. moonwatch is not running, so any
      # saved data is stale; clear it as a start would, so moon and sun
      # checks see nothing up rather than old timers. Look again first:
      # a moonwatch started another way since the check above has just
      # written its skeleton, which must not be wiped. Writing only when
      # there is something to clear keeps this off the usual path (the
      # failed start already cleared the data). A moonwatch started in
      # the moment between that last look and the write can still lose
      # its skeleton; only moonwatch itself could close that window.
      return await_running_moonwatch(timeout) if Script.running?('moonwatch')

      UserVars.moons = {} unless UserVars.moons == {}
      UserVars.sun = {} unless UserVars.sun == {}
      return false
    end

    Lich::Messaging.msg("bold", "DRCMM: moonwatch is not running. Starting it now.")
    @moonwatch_data_stalled = false
    UserVars.moons = {}
    UserVars.sun = {}
    started = start_script('moonwatch') ? true : false
    if !started && !Script.running?('moonwatch') && !moonwatch_findable?
      Lich::Messaging.msg("bold", "DRCMM: moonwatch could not be found. Moon data is unavailable.")
      note_moonwatch_start_failure(timeout)
      return false
    end
    if await_moonwatch_data(started, timeout)
      # Only suggest autostart once this start has actually worked.
      Lich::Messaging.msg("plain", "DRCMM: Run `#{$clean_lich_char}e autostart('moonwatch')` to avoid this in the future.") if started
      return moonwatch_data_ready!
    end

    note_moonwatch_start_failure(timeout)
    false
  ensure
    release_moonwatch_start_lock if MOONWATCH_START_LOCK.owned?
  end
end

.moon_data_ready? ⇒ Boolean

Whether UserVars.moons holds real moon data: every moon has a numeric 'timer' and 'visible' is a list. moonwatch first writes an empty skeleton (=> {, ..., 'visible' => []}) and fills in the timers afterwards, so the skeleton does not count as ready.

moonwatch sets 'running' to false when it exits. UserVars persist between sessions, so data marked that way is left over from a moonwatch that has stopped and does not count as ready either. Data without a 'running' key (older moonwatch versions) is judged by the timers alone.

moonwatch publishes the moons first and the sun right after, and the celestial checks read both. So while moonwatch has marked UserVars.sun as running but not yet written its 'timer' (the last key those checks read, written after 'day'), the data is not ready. Sun data without a 'running' key (older moonwatch versions) is not checked.

moonwatch's 'running' => false marker is saved only when Lich shuts down in an orderly way. After a crash the saved data can still say 'running' => true, and while a newly started moonwatch has not yet written its skeleton (normally a few milliseconds) that saved data counts as ready.

Returns:

  • (Boolean)

def moon_data_ready?
  moons = UserVars.moons
  return false unless moons.is_a?(Hash) && moons['visible'].is_a?(Array)
  return false if moons['running'] == false
  return false unless MOON_NAMES.all? { |moon| moons[moon].is_a?(Hash) && moons[moon]['timer'].is_a?(Numeric) }

  sun = UserVars.sun

def parse_roisaen(text)
  return nil if text.nil?
  return nil if $NUM_MAP.nil?

  words = text.downcase.tr('-', ' ').split
  return nil if words.empty?
  return nil unless words.all? { |word| $NUM_MAP.key?(word) }

  words.sum { |word| $NUM_MAP[word] }
end

def set_planet_data(data, settings = nil)
  return data unless data['stats']

  planets = get_data('constellations')[:constellations].select { |planet| planet['stats'] }
  planet_names = planets.map { |planet| planet['name'] }
  # find_visible_planets returns nil when there is no telescope to look through.
  visible_planets = find_visible_planets(planet_names, settings) || []
  data['stats'].each do |stat|
    cast_on = planets.map { |planet| planet['name'] if planet['stats'].include?(stat) && visible_planets.include?(planet['name']) }.compact.first
    next unless cast_on

    data['cast'] = "cast #{cast_on}"
    return data
  end
